# OpenViking Experience 融合实施计划

## 1. 状态与目标

本文保存已讨论的融合方案、分阶段交付和启用门槛，作为后续代码实施输入；不是功能已实现、生产开关已开启或会话数据已获上传授权的声明。

当前实现边界见 [主集成计划](openviking-integration-plan.md)：Evolve 已有项目资产同步、Session 版本固定、证据归因、冻结知识回放、合并验证及 CAS 发布。原生 Experience 读取、OpenViking 会话采集和经验驱动候选仍待实现。

目标是让 OpenViking 负责原生经验的积累、召回及使用结果关联，让 Evolve 保持任务状态、项目约束、Skill 修改决策、验证与发布的权威。不得合并两套 Session 状态机，不得新增平行的 Skill 发布系统。

## 2. 先区分开发推进与生产启用

- **开发推进**：当前阶段的接口契约、针对性测试、隔离场景和审查通过后，才进入依赖它的下一阶段开发。
- **生产启用**：功能已验收还不够；必须满足该项目的数据权限、管理员配置及发布策略。读取经验、采集会话、生成候选、自动应用/发布分别授权。
- 新能力默认不影响已有项目；未显式启用时不增加网络请求、会话上传或模型调用。下述开关是设计边界，尚不是可执行配置字段或 CLI 参数。
- 不按固定天数、经验数量或界面是否有记录升级，也不因前一阶段完成自动开启后一阶段。
- 可以长期只开启经验读取。采集开关关闭不妨碍读取已有的授权经验；自动发布也不要求跟随候选生成开关开启。

## 3. 阶段一：只读经验接入与快照固定

### 交付

在现有统一知识入口旁接入原生 Experience 来源，供 CLI、HTTP、Run MCP 一致读取；不冒用现有项目 release Memory ID，不改变正式 Wiki 约束的治理路径。

按任务、项目、环境及来源筛选，精读选中正文，保存 URI、内容哈希、读取时间和来源关联。没有明确适用证据的经验只作为一般参考，不授予项目修改权限。

在新 Evolve Session 准备时固定经验快照。该 Session 的执行、归因和基线/候选回放使用相同内容；远端更新不能改变既有快照。经验读取属于建议性上下文，不得绕过现有 Skill/Wiki 的版本与完整性检查。

### 验收门槛 G1

- 经验命中、无命中、来源不适用和来源不足时的行为可核验，不能强制补入无关经验。
- CLI、HTTP、Run MCP 精读同一条经验时，URI、正文和哈希一致。
- 旧 Session 保持旧快照；后续 Session 能获取新内容；缓存被篡改时明确失败。
- 未启用时没有新增请求；可用性故障按明确的经验策略处理，不冒充读取成功、不撤销业务完成、不削弱其他资产的 fail 策略。
- 读取经验不会写入原生会话、触发提取、修改 Skill 或成为正式约束。
- 有针对性消费者测试及实际入口证明；真实服务使用隔离账号或明确授权测试范围。没有真实服务条件时标记缺口，不将协议 fixture 称作真实服务证明。

### 下一步条件

G1 全部有证据，且没有未解决的阻断性问题，才开始阶段二的集成开发。阶段一不要求截图出现新经验，也不自动授权上传。

## 4. 阶段二：受控会话采集与原生经验生成

### 交付

先核对宿主是否已有官方会话捕获与提交能力，有则复用；无则实现所需桥接，不重复采集同一份会话。

持久化 Evolve Session/Run 与 OpenViking Session 的关联及已确认发送进度，不复用相同 ID 来假定两者相同，也不强制一对一。仅发送明确允许共享的任务信息、结果和真实执行证据，默认不上传原始私人对话、凭据或整个工作区。

将会话写入、commit 受理、后台提取完成分开记录。对结果未知的写入先核对，不能盲目重发造成重复；服务故障保留可恢复状态，不伪造经验生成成功。

原生经验使用关联只能来自真实搜索/精读及实际捕获的工具证据。不支持宿主关联时明确说明限制，不合成 ToolPart 或将普通注入计作原生经验使用。

### 开发验收门槛 G2

- 映射、重复调用、进程中断和未知结果恢复保持已确认进度，不把一个业务会话重复采集为多份经验来源。
- 缺少权限、提取失败或服务不可用时，业务状态与经验采集状态独立且准确；不改变资产发布失败的真实性。
- 隔离真实场景能核对提交的来源记录、提取任务终态和所生成经验；accepted/task_id 本身不算完成。
- 缺省不上传；拒绝或缩小授权后不继续发送超范围数据；实际测试确认禁止共享字段未发送。
- 会话来源、原生经验及其后续真实读取/轨迹关联可追溯；不能将关联统计当作因果验证。

### 真实项目启用门槛 A2

必须明确允许的项目、数据字段、会话范围和数据去向，并确认账号管理员已开启所需原生进化能力、提取模型和权限可用。G2 通过不会自动满足 A2。

A2 未满足时，生产采集保持关闭，不因此禁止用户继续只用阶段一。

## 5. 阶段三：经验辅助 Skill 候选决策

### 交付

将冻结的 Experience 与本地已封存的 Run 证据一起提供给现有 review/候选流程。经验用于提出假设，不替代本地来源接地及缺陷归因；区分 Skill 缺陷、环境故障、权限问题、模型输出和工具异常。

候选继续沿用现有 draft、冻结知识回放、三方合并、最终提交复验、apply/rollback 和 CAS 发布，不增加第二套引擎。无可归因信号时保持零修改。

长期 Experience 由 OpenViking 维护；Evolve review 负责归因和候选，不再独立提炼一套同类长期经验并双向回灌。保留本地个人记忆和正式 Wiki 的既有治理边界。

### 验收门槛 G3

- 陈旧、跨项目、冲突或缺少来源证据的经验不能直接触发项目修改；相似标题和任务成功统计不能替代证据。
- 基线、候选与合并结果使用相同 Skill/知识/经验输入；目标失败得到修复，原成功路径没有回退。
- 回放失败、最终验证失败、内容损坏或发布冲突时，不推进已发布版本，保留诊断及恢复材料。
- 能从候选、回放和最终 release 追溯到本地 Run 证据与原始 Experience 快照。
- 隔离端到端验证覆盖真实模型和真实服务后，才可把无人值守闭环标为已验证。协议模型、受理状态和经验计数均不能替代该证明。

### 启用门槛 A3

候选生成与自动应用/发布分开控制。默认可以只审查候选；自动应用/发布必须另有明确项目策略授权，并完成 G3。开启读取或采集不隐含此授权。

阶段三依赖 G1 的快照契约和可信 Run 证据。如果使用已有授权经验，不技术性强制要求生产采集开启；首轮完整接入仍先验收 G2 的来源闭环，再开放自动化策略。

## 6. 升级决策与停止规则

| 决策点 | 需要的证据 | 通过后的动作 | 不通过时 |
|---|---|---|---|
| 阶段一进入阶段二开发 | G1 的测试、入口与隔离场景结果，审查无阻断项 | 开始会话桥接开发；生产上传仍关闭 | 留在只读接入，修复问题 |
| 开启真实项目采集 | G2 + A2 | 仅在授权项目及字段范围内采集 | 继续只读，不自动上传 |
| 开始经验驱动候选集成 | G1 稳定契约、可信 Run 来源；首轮完成 G2 来源验证 | 接入现有候选流程，不默认应用或发布 | 不生成缺少接地证据的候选 |
| 开启自动应用/发布 | G3 + A3 | 按现有策略进行验证后发布 | 保留人工审查候选或现有稳定版本 |

每次进入下一阶段，保存对应 Run 的验证制品、未验证限度和权限决定。数据范围、公共接口或发布权限扩大时重新决策；不得把文档中的门槛名称当成当前已经实现的 Runtime gate。

## 7. 开始实施的顺序

1. 以本文为输入，先制定并执行**仅阶段一**的代码计划，完成实现、定向验证和审查。
2. 记录 G1 结果，再决定阶段二开发；不把三个阶段作为无条件自动执行链。
3. 阶段二涉及真实数据上传，必须在 A2 决策后才启用；阶段三的自动应用/发布在 A3 决策后才启用。

当前持久化的是方案和门槛，运行时代码尚未接入上述能力。保存方案不等于已实现阶段一，也不等于已授权 A2/A3。
